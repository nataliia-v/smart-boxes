# Smart Box

QR-first домашній каталог: Google-вхід для власника, коробки й речі, гостьовий доступ без реєстрації, приватні фото у Drive власника.

**v2 з чистого листа.** Старий тестовий Apps Script збережений лише в історії Git. Дані з Google Sheets не імпортуються. Новий код не потребує Sheets, Apps Script чи `clasp`.

## Локальний запуск

Node.js 22+:

```sh
npm ci
npm run dev
```

- `http://localhost:3000` — головна сторінка.
- `/setup` — підказки, коли секрети ще не налаштовані.

Для роботи потрібні PostgreSQL, Google OAuth і серверні змінні середовища, описані нижче. Без конфігурації API повертає 503, а сайт показує інструкцію налаштування. Власник входить через Google; гість відкриває конкретну коробку за QR без входу.

## Стек і структура

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, Auth.js 5 (зафіксована beta.32), Prisma 6, PostgreSQL, Google Drive REST API, Vercel. Залежності зафіксовані lockfile; Prisma 6 використовується свідомо, Auth.js beta потребує перевірки живого Google OAuth перед запуском.

```text
src/app/                  сторінки, API, manifest, іконки
src/components/           український UI
src/server/inventory.ts   транзакції, CRUD, права, історія
src/server/access.ts      перевірки owner / guest
src/server/drive.ts        Google OAuth refresh, папки, файли
src/server/photos.ts      серверна перевірка фото та видача
src/auth.ts               Auth.js + Prisma, шифровані OAuth-токени
src/lib/                  валідація, типи, стиснення, транслітерація
prisma/                   схема та початкова міграція
tests/                    unit та реальні PostgreSQL integration tests
scripts/cleanup-photos.ts прибирання незавершених завантажень
docs/CHECKLIST.md          виконані кроки й перевірки після підключення
```

## Правила першої версії

- Нова коробка — **VIEW**. Власник може вибрати EDIT або PRIVATE.
- Порядок коробок можна змінювати затиском картки приблизно на 400 мс та перетягуванням (миша, touch або клавіатура: пробіл → стрілки → пробіл). Короткий тап відкриває коробку, рух до активації дозволяє прокручувати сторінку. Порядок зберігається в PostgreSQL для власника; нові коробки з’являються першими.
- Натискання на результат пошуку у всіх коробках відкриває коробку на сторінці потрібної речі та підсвічує її. Усередині коробки натискання відкриває редагування. Пошук очищується кнопкою ×.
- Скасування системного вибору файла не закриває форму речі. Для закриття форми використовуйте × або «Скасувати».
- EDIT-гості можуть додавати, редагувати й прибирати речі тільки конкретної коробки.
- Налаштування, видалення коробки, QR-ротація, історія й відновлення — лише власнику.
- Фото необов’язкове. Номери автоматичні в межах коробки, не повторюються після видалення.
- Речі й коробки видаляються логічно; речі можна відновити в «Прибрані». Відновлення цілої коробки через UI не реалізовано.
- У «Прибрані» власник також може остаточно видалити річ разом із фото на Drive. Після збереження заміни/прибирання фото старий файл також видаляється остаточно. Історія події та назва речі залишаються.
- QR містить випадковий 256-бітний token. Його заміна скасовує старий URL; налаштування перевіряються на кожному запиті.
- Зміни речей та історія записуються в одній транзакції. `version` захищає від перезапису застарілими формами. UUID-запит захищає повторне створення речі.
- PostgreSQL rate buckets спільні між Vercel-інстансами. Обмежуються публічні читання, зміни та фото. Фото-проксі й дані мають `private, no-store`; service worker та offline-черга не використовуються.

## 1. База PostgreSQL

Можна використати Neon або інший PostgreSQL. Для локальної розробки:

```sh
docker compose up -d
```

Створіть **`.env`** у корені за прикладом `.env.example`. Next.js і Prisma CLI читають `.env`; не комітьте його. `.env.local` читає Next.js, але Prisma CLI автоматично його не читає.

- `DATABASE_URL` — робоче підключення (у Neon можна pooled).
- `DIRECT_URL` — пряме підключення для міграцій.

```sh
npm run db:migrate
```

Міграції застосовуйте окремим контрольованим кроком, до запуску нової версії. `npm run build` не змінює production-базу. Preview/test та production мають використовувати різні бази. Увімкніть резервні копії у провайдера.

## 2. Google Cloud / OAuth

1. Створіть проєкт Smart Box у Google Cloud.
2. Увімкніть **Google Drive API**.
3. Налаштуйте Google Auth Platform / OAuth consent: назву, email та audience External. Для тестування додайте акаунти власників до Test users. Гості за QR не потребують Google-акаунта.
4. Запитані scopes: `openid email profile https://www.googleapis.com/auth/drive.file`.
5. Створіть OAuth client **Web application**.
6. Authorized redirect URIs:
   - `http://localhost:3000/api/auth/callback/google`
   - `https://ВАШ-ДОМЕН/api/auth/callback/google`
7. Внесіть client ID / secret у `AUTH_GOOGLE_ID` / `AUTH_GOOGLE_SECRET`.

`drive.file` дозволяє працювати лише з файлами, доступними цьому OAuth-застосунку. Ми створюємо власну папку `Smart Box/Photos` під час першого завантаження. Існуючі сторонні файли не імпортуються. Власник має надати Drive scope та offline-доступ; refresh token може вимагати повторної згоди (вхід запитує consent).

OAuth у режимі **Testing** може мати короткоживучі refresh tokens для Drive scopes. Перед тривалим публічним використанням переведіть OAuth у production, налаштуйте домен, сторінки приватності/умов і пройдіть необхідні Google-перевірки. Гості ніколи не отримують Google-токени.

## 3. Секрети

Згенеруйте **два різні** значення:

```sh
openssl rand -base64 32
openssl rand -base64 32
```

Перше — `AUTH_SECRET`, друге — `TOKEN_ENCRYPTION_KEY`. OAuth access/refresh tokens у Account зберігаються AES-256-GCM-зашифрованими, ID token не зберігається. У браузері лише opaque HttpOnly session cookie; токени не додаються до session payload. Ключ шифрування не змінюйте без процедури перешифрування: інакше користувачам потрібно повторно підключити Google.

`APP_URL` — точний origin без шляху/кінцевого слеша, наприклад `https://smartbox.example`. Це база постійних QR та дозволений Origin для mutation-запитів. На Vercel Auth.js довіряє платформному proxy; на іншому trusted proxy може знадобитися `AUTH_TRUST_HOST=true`.

## 4. Vercel

1. Import Project → репозиторій → Next.js, Node 22.
2. Додайте server environment variables з `.env.example` (без `NEXT_PUBLIC_` для секретів).
3. Застосуйте міграції до production-БД.
4. Deploy. Build command: `npm run build`.
5. Перевірте Google-вхід, фото власника, фото гостя при відсутній сесії власника, VIEW/EDIT/PRIVATE та відкликання QR.
6. Підключіть постійний домен **перед друком постійних QR**. Оновіть APP_URL і Google callback URI.

GitHub workflow тепер лише перевіряє код і тестує на тимчасовому PostgreSQL. Деплой виконує інтеграція Vercel із GitHub. Видаліть старий `CLASPRC_JSON` і `APPS_SCRIPT_DEPLOYMENT_ID` у GitHub, вимкніть старе розгортання Apps Script вручну. Google-таблиця та стара папка не видаляються цим кодом.

### Автоматичний деплой після push

У налаштуваннях Vercel перевірте підключений Git-репозиторій `nataliia-v/smart-boxes` та Production Branch `main` (у розділі Git або Environments → Production, залежно від інтерфейсу). За ввімкненої Git-інтеграції кожен push у `main` автоматично запускає production-збірку; вручну Create Deployment натискати не потрібно. Інші гілки створюють Preview deployments. GitHub Actions перевіряє код окремо: Vercel за замовчуванням не чекає його результату.

Перший успішний запуск потребує environment variables у Vercel: `APP_URL` — постійний production-origin без кінцевого слеша; `AUTH_URL`, якщо заданий, має відповідати йому, а не localhost/ngrok. Додайте `${APP_URL}/api/auth/callback/google` у Google OAuth redirect URIs. Після зміни лише environment variables потрібен Redeploy або наступний push. У разі відсутності автоматичного запуску перевірте Git-інтеграцію, доступ Vercel до репозиторію та повідомлення про автора коміту (особливо для приватного репозиторію на Hobby).

## Фото і помилки

- На клієнті фото до 25 МБ стискається до JPEG ≤1,5 МБ / 1200 px. HEIC залежить від браузера; якщо не декодується, оберіть JPEG/PNG чи камеру.
- Сервер обмежує multipart body, реально декодує JPEG/PNG/WebP через sharp, обмежує пікселі, повторно кодує й видаляє metadata.
- Файли залишаються **приватними** в Drive власника. Гість завантажує через сервер; фото видається лише за актуальним доступом до відповідної речі/коробки.
- Перед Drive upload у БД резервується Media та pre-generated Drive file ID. Після upload права перевіряються повторно. Помилка залишає запис для повторного прибирання. Вікно між Drive та БД не є спільною транзакцією.
- Не прикріплені фото зберігаються 24 години для повторення запиту; фото прикріплених, зокрема soft-deleted, речей зберігаються до остаточного видалення. При заміні фото чи остаточному видаленні речі транзакція ставить старому Media `deletionRequestedAt`, після чого виконується Drive `DELETE`. Нове фото не видаляється, якщо запит до Drive для старого файла не вдався.
- Невдале видалення не скасовує вже збережені зміни: UI повідомляє про очікування повторної спроби. Черга повторно обробляється у фоні при завантаженні профілю власника та скриптом cleanup. Гість не може остаточно видалити річ або використати фото, уже поставлене в чергу видалення.

Періодично запускайте з налаштованим server env (наприклад щоденним зовнішнім scheduler):

```sh
npm run photos:cleanup
```

Скрипт обробляє до 100 старих orphan uploads за запуск і чистить прострочені rate buckets. На Vercel його можна запускати з окремого довіреного CI/scheduler; автоматичний scheduler без налаштованих секретів не створений. Після редагування назви речі ім’я вже завантаженого файла не змінюється; ім’я фіксується під час upload (транслітерований title + UUID фото). Видалення акаунта/self-service disconnect та остаточне стирання Drive-даних — окремий незавершений продуктовий крок; не видаляйте User напряму до визначення політики збереження.

Якщо власник відкликав Google-дозвіл або Drive заповнений, текстовий каталог залишається доступним, а фото-запит повертає зрозумілу помилку без OAuth-деталей. Власник може повторно увійти, щоб оновити згоду. Видалену папку система створить заново для нових фото; старі видалені файли не відновлює.

## Перевірки

```sh
npm run check
npm test
npm run build
```

Для інтеграційних тестів потрібна **окрема** порожня PostgreSQL-база з `test` у назві URL; тести самі створюють і видаляють лише своїх користувачів:

```sh
DATABASE_URL="postgresql://.../smartbox_test" DIRECT_URL="postgresql://.../smartbox_test" npm run db:migrate
DATABASE_URL="postgresql://.../smartbox_test" DIRECT_URL="postgresql://.../smartbox_test" npm run test:integration
```

Тести перевіряють права, чужі ID, токени, шифрування, справжнє декодування фото, одночасні номери, replay, історію та recovery. Живий Google OAuth/Drive перевіряється після отримання credentials, а не підмінюється успіхом тестів. Повний чекліст — `docs/CHECKLIST.md`.

## PWA

Є web manifest, PNG 192/512 та Apple 180, maskable icon, standalone display, start URL `/app/boxes`. На iPhone: Safari → Share → Add to Home Screen. Сесія й Google login у standalone потребують перевірки на реальному iPhone. QR відкриває звичайну HTTPS-сторінку, інсталяція не потрібна. Offline, push та AI навмисно відкладені.
