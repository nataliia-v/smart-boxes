# Smart Boxes

Український вебінтерфейс для речей у коробках. Кожна коробка — вкладка Google Sheets; фотографії завантажуються в Google Drive і **відображаються зображеннями в клітинках**.

Без окремого сервера, платного хостингу або frontend-залежностей: HTML/CSS/JavaScript + Google Apps Script.

## Можливості

- Створення коробки за назвою, картки речей та пошук за назвою, описом, номером і коробкою.
- Додавання, редагування, видалення речей. Назва й фото обов’язкові, опис — ні.
- Автоматичні номери в кожній коробці; видалення не перенумеровує решту речей.
- Фото з галереї або камери, попередній перегляд, зменшення до 1200 px та JPEG до 1,5 МБ.
- Назви фото: транслітерований `title` + UUID речі, наприклад `pazly-miaki_01234567-89ab-cdef-0123-456789abcdef.jpg`.
- Перейменування завантаженого файлу при зміні назви речі через інтерфейс.
- Посилання на конкретну коробку: `…/exec?box=673832429`. Його можна закодувати в QR; генератор QR не входить до цієї версії.
- Блокування паралельних записів, захист від повторного створення при повторі запиту, перевірка конфлікту редагування.

## Локальний перегляд

Потрібен Node.js 22+. Встановлення пакетів не потрібне.

```sh
npm run dev
```

Відкрийте **http://127.0.0.1:4173**. Це явно позначений демо-режим із тестовими речами. Він використовує `localStorage`, не звертається до Google і не змінює справжню таблицю. Для скидання демо видаліть ключ `smart-boxes-demo-v1` у сховищі браузера. Локальна адреса доступна лише на цьому комп’ютері.

```sh
npm run check
npm test
```

Тести виконують серверний код із підміною сервісів Google та перевіряють імпорт, збереження зображень, номери, конфлікти, повторні запити, валідацію та транслітерацію. Реальні дозволи Drive та вставлення зображення перевіряються після розгортання.

## Автоматичне підключення GitHub → Google Apps Script

Workflow **Publish to Google Apps Script** у `.github/workflows/apps-script.yml` запускає перевірки та після кожного push у `main` завантажує код із `apps-script/`. Для pull request виконуються лише перевірки. Запуск вручну: [Actions → Publish to Google Apps Script](https://github.com/nataliia-v/smart-boxes/actions/workflows/apps-script.yml) → **Run workflow → main → Run workflow**.

Проєкт уже прив’язано через `.clasp.ci.json` до [вашого Apps Script](https://script.google.com/home/projects/1j6kw_7QvnJk6nPJlkS1Q4U29UZLqav_JIG71RbxVXo_Ap7zGjbZ4CPXt/edit). Script ID не є паролем. Облікові дані зберігаються окремо в GitHub Secret.

### 1. Авторизація (один раз)

1. Увімкніть **Google Apps Script API** в [налаштуваннях Google](https://script.google.com/home/usersettings).
2. На своєму комп’ютері виконайте `npx @google/clasp@3.4.1 login` та підтвердьте вхід в акаунт власника проєкту. Якщо вже авторизувалися через `clasp login`, повторювати не потрібно.
3. На Mac виконайте `pbcopy < ~/.clasprc.json`.
4. У [Settings → Secrets and variables → Actions → Secrets](https://github.com/nataliia-v/smart-boxes/settings/secrets/actions) створіть **New repository secret** з назвою **`CLASPRC_JSON`**, вставте весь JSON та збережіть. Не додавайте цей файл до Git і не вставляйте його у повідомлення чи логи.
5. Запустіть workflow через **Run workflow**. Код з’явиться в редакторі Apps Script після успішного кроку **Upload code to Apps Script**. Встановлювати `clasp` на GitHub вручну не потрібно — workflow робить це сам.

### 2. Перша публікація інтерфейсу (один раз)

1. Відкрийте [проєкт Apps Script](https://script.google.com/home/projects/1j6kw_7QvnJk6nPJlkS1Q4U29UZLqav_JIG71RbxVXo_Ap7zGjbZ4CPXt/edit), оновіть сторінку, виберіть `Code.gs` та запустіть **`setup`**. Надайте запитані дозволи на таблицю і Drive.
2. **Deploy → New deployment → Web app → Execute as: Me → Who has access: Anyone → Deploy**.
3. Скопіюйте **Deployment ID** з **Deploy → Manage deployments**. Це не Script ID: потрібна частина URL між `/s/` і `/exec`.
4. У [Settings → Secrets and variables → Actions → Variables](https://github.com/nataliia-v/smart-boxes/settings/variables/actions) натисніть **New repository variable**. Назва — **`APPS_SCRIPT_DEPLOYMENT_ID`**, значення — Deployment ID (не повний URL).
5. Знову запустіть workflow. Відтепер кожен push у `main` також створюватиме версію й оновлюватиме це розгортання. URL інтерфейсу і коробок залишиться тим самим.

Без `APPS_SCRIPT_DEPLOYMENT_ID` workflow успішно завантажує код **лише в редактор** та показує наступні кроки в Summary. Для оновлення вже опублікованого `/exec` потрібна ця змінна. Авторизація `clasp` надає доступ до керування кодом, а початковий запуск `setup` окремо надає самому вебінтерфейсу доступ до даних.

GitHub є джерелом коду: наступне завантаження замінює файли у редакторі Apps Script файлами репозиторію. Зміни в коді потрібно вносити в репозиторій. Завантаження коду саме по собі не запускає `setup` і не змінює рядки таблиці.

### Якщо workflow завершився з помилкою

- **CLASPRC_JSON missing / invalid** — додайте повний JSON у repository secret з точною назвою `CLASPRC_JSON`.
- **invalid_grant / invalid credentials** — повторіть `npx @google/clasp@3.4.1 login` та оновіть secret.
- **Apps Script API disabled** — увімкніть API в налаштуваннях акаунта, зачекайте кілька хвилин і натисніть **Re-run failed jobs**.
- **Permission denied / project not found** — авторизований Google-акаунт повинен мати доступ редактора до заданого проєкту.
- **Deployment not found** — перевірте `APPS_SCRIPT_DEPLOYMENT_ID`: це ID розгортання саме цього проєкту, створеного тим самим акаунтом.

## Ручне підключення до Google (якщо не використовуєте GitHub Actions)

### 1. Відкрити Apps Script

У [таблиці smart_boxes](https://docs.google.com/spreadsheets/d/1uPg36Fz-9Yp8OdbToPm9OQZooUMffQ22B1Z85pIRMjw/edit) відкрийте **Розширення → Apps Script**. Назвіть проєкт `Smart Boxes`.

### 2. Додати файли

Скопіюйте в редактор файли з папки `apps-script/`:

| Файл у репозиторії | Як створити в редакторі |
| --- | --- |
| `Config.gs` | Script → `Config` |
| `Code.gs` | Вміст початкового `Code.gs` замінити цим кодом |
| `Photos.gs` | Script → `Photos` |
| `Index.html` | HTML → `Index` |
| `Styles.html` | HTML → `Styles` |
| `Client.html` | HTML → `Client` |

У **Project Settings / Налаштування проєкту** увімкніть **Show “appsscript.json” manifest file in editor**. Замініть вміст цього файлу на `apps-script/appsscript.json` із репозиторію. Збережіть усі файли.

`tools/`, `tests/`, `package.json` не потрібно переносити в Apps Script.

### 3. Перевірити налаштування

У `Config.gs` уже задано:

```js
spreadsheetId: '1uPg36Fz-9Yp8OdbToPm9OQZooUMffQ22B1Z85pIRMjw',
photoFolderId: '1q6-kmqzzwL8CsqCFnOspcxWRMPXQAyhD'
```

Акаунт, від якого публікується скрипт, повинен мати право редагувати таблицю й додавати файли до [папки фотографій](https://drive.google.com/drive/folders/1q6-kmqzzwL8CsqCFnOspcxWRMPXQAyhD).

### 4. Перший запуск

У редакторі відкрийте `Code.gs`, виберіть функцію **`setup`** у списку біля Run і натисніть **Run / Виконати**. Надайте своєму скрипту запитані дозволи Google Sheets, Drive та зовнішніх запитів (вони потрібні для отримання зображень із Drive). Якщо Google показує екран неперевіреного власного проєкту, перевірте, що це щойно створений вами `Smart Boxes`.

У журналі мають з’явитися назви таблиці, папки та кількість коробок. Функція також ініціалізує приховані службові колонки й лічильники. Функції з `_` наприкінці недоступні для виклику через `google.script.run` з браузера.

### 5. Опублікувати інтерфейс

1. **Deploy → New deployment → Web app**.
2. **Execute as: Me** — виконувати від вашого акаунта.
3. **Who has access: Anyone** — усі, включно з відвідувачами без входу в Google.
4. Натисніть **Deploy** та відкрийте URL, який закінчується на **`/exec`**.

Це узгоджений режим: **кожен із посиланням може переглядати, додавати, редагувати й видаляти речі**, а також створювати коробки. Таблицю та папку окремо відкривати для всіх не потрібно. Деякі Google Workspace-акаунти обмежують публікацію `Anyone` або публічні файли Drive — тоді потрібен акаунт, у якому ці можливості дозволені.

Для оновлення коду: **Deploy → Manage deployments → Edit → Version: New version → Deploy**. Оновлюйте наявне розгортання, щоб посилання на коробки залишалися тими самими. URL `/dev` призначений тільки для редакторів скрипта.

## Структура вкладки

| Рядок | A | B | C | D | E (прихована) | F (прихована) |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | Назва коробки, можна об’єднати клітинки A:D | | | | | |
| 2 | № | Title | Photo | Description | _smart_boxes_id | _smart_boxes_photo_id |
| 3+ | Номер | Назва | Зображення в клітинці | Опис | UUID речі | ID файлу Drive |

Існуючий заголовок у рядку 1 й фото не перезаписуються під час імпорту. Підтримуються також заголовки `Назва / Фото / Опис`. Порожній D2 заповнюється `Description`. Вкладки з іншими заголовками пропускаються з повідомленням.

Перший запуск записує UUID для наявних речей у E, а F використовує лише для фото, завантажених через інтерфейс. Якщо E або F уже зайняті сторонніми даними, скрипт зупиняється з поясненням. Потрібно спершу перенести ці дані в інші колонки. Службові колонки не слід вручну редагувати. Якщо сортуєте таблицю, сортуйте всі колонки рядка разом, включно з E–F.

Назва коробки в інтерфейсі береться з назви вкладки, посилання — з її незмінного числового ID. Номери у A мають бути унікальними додатними цілими числами. Максимальний використаний номер зберігається в **Script Properties**; не очищуйте їх, якщо потрібно зберегти історію номерів. Після невдалого завантаження можливий пропуск номера. Зміни, внесені безпосередньо в Sheets, відображаються після натискання «Оновити».

## Як працюють фото

1. Браузер декодує фото, зменшує його й конвертує в JPEG. Якщо браузер не читає HEIC, потрібно вибрати JPEG/PNG або скористатися камерою.
2. Apps Script перевіряє розмір і формат та створює файл у заданій папці.
3. **Лише новому файлу** встановлюється `Anyone with the link → Viewer`. Це дає Google Sheets доступ до джерела зображення. Папка не стає публічною.
4. Скрипт перевіряє доступність thumbnail URL Drive і вставляє `CellImage` у C, а ID файлу записує у F. Рядок отримує висоту 150 px.
5. Для вебсторінки скрипт отримує тимчасовий `CellImage.getContentUrl()`. Він придатний для перегляду без входу; при помилці завантаження інтерфейс один раз запитує свіжий URL.

Наявні фото в клітинках читаються без перенесення в Drive. Фото, розміщені **поверх клітинок**, не є `CellImage` — їх потрібно вставити в клітинку через меню Sheets. Імпорт з Excel необхідно перевірити на реальних зображеннях після розгортання. Є також читання HTTPS-посилань та простих формул `=IMAGE("https://…")`.

При редагуванні тексту без заміни фото клітинка C не змінюється. При заміні створюється новий файл із тим самим шаблоном назви (Drive допускає однакові назви), а клітинка отримує нове зображення. Попередні файли та фото видалених речей **залишаються в папці**; їх можна прибрати вручну. Для імпортованих фото без ID у F перейменування файлу не виконується.

## Перевірка після публікації

Локальні тести не замінюють перевірку сервісів Google. Після першого розгортання:

1. Відкрийте каталог: мають бути обидві наявні коробки, правильні номери й фотографії.
2. Створіть тестову коробку. Перевірте назву вкладки та заголовки в рядку 2.
3. Додайте тестову річ із телефона: фото має бути видно **і на картці, і в C3**, а JPEG — у папці Drive.
4. Змініть назву й опис без заміни фото: фото зберігається, ім’я файлу оновлюється.
5. Замініть фото; перевірте картку та клітинку ще раз.
6. Видаліть тестову річ і додайте іншу: номер не повторюється.
7. Відкрийте ту саму річ у двох вкладках браузера. Після збереження в першій друга має повідомити про конфлікт.
8. Перевірте `/exec` та посилання коробки у приватному вікні без входу в Google.

Якщо фото не вставляється, перевірте, чи дозволений доступ `Anyone with the link` до створеного JPEG, та журнал **Executions** в Apps Script. Thumbnail URL Drive — інтеграційна залежність, яку потрібно перевірити саме у вашому акаунті. Якщо запис не вдався, інтерфейс залишить форму відкритою з помилкою.

## Файли

```text
apps-script/    Код для Google Apps Script та HTML-інтерфейс
tools/          Локальний HTTP-перегляд, демо-адаптер, перевірка синтаксису
tests/          Перевірки серверної логіки на Node.js
```

Прив’язка для GitHub Actions зберігається в `.clasp.ci.json` (`rootDir: "apps-script"`). Локальний `.clasp.json` та облікові дані `.clasprc.json` виключені з Git.
